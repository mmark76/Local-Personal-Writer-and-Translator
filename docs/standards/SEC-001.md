# SEC-001 — Cybersecurity Standards

**Project:** Local Personal Writer and Translator  
**Version:** 0.1  
**Date:** 10 November 2026  
**Status:** APPROVED  
**Infrastructure:** LOCAL_ONLY — Windows + Ollama  
**Authority:** Ecosystem Security — The Shield

## 1. Σκοπός

Το SEC-001 καθορίζει τις απαιτήσεις κυβερνοασφάλειας για την εφαρμογή Local Personal Writer and Translator.

Κύριος στόχος είναι η προστασία:

- Των προσωπικών κειμένων και εγγράφων.
- Των αρχικών και παραγόμενων δεδομένων.
- Του τοπικού υπολογιστή.
- Της επικοινωνίας με τα μοντέλα Ollama.
- Του repository και της διαδικασίας ανάπτυξης.
- Της ακεραιότητας και διαθεσιμότητας της εφαρμογής.

**Βασική αρχή: Security by Design — η ασφάλεια ενσωματώνεται στον σχεδιασμό και επαληθεύεται στην πράξη.**

## 2. Κανονιστική βάση

Η επίσημη πηγή απαιτήσεων κυβερνοασφάλειας είναι το Ecosystem Security — The Shield.

Το SEC-001 αποτελεί την εξειδίκευση των εφαρμοστέων απαιτήσεων στο συγκεκριμένο project. Δεν δημιουργεί δεύτερο γενικό security framework.

Υιοθετούμε τις αρχές:

- Security by Design
- Least Privilege
- Defense in Depth
- Zero Trust, όπου απαιτείται από τον κίνδυνο
- Fail Closed
- Data Minimization
- Controlled Changes
- Evidence-Based Verification

Η υιοθέτηση θα τεκμηριώνεται σύμφωνα με το Security Adoption and Verification του Ecosystem Framework — The DNA.

## 3. SEC-01 — Local-First Security Boundary

Η εφαρμογή θα λειτουργεί αποκλειστικά στον προσωπικό Windows υπολογιστή κατά την αρχική έκδοση.

Αρχική επιτρεπόμενη διαδρομή:

```text
User
  ↓
Local Application
  ↓
Local Ollama Adapter
  ↓
127.0.0.1:11434
  ↓
Installed Local Model
  ↓
Local Result
```

### Απαιτήσεις

- Η τοπική υπηρεσία της εφαρμογής, εφόσον υπάρχει, θα δεσμεύεται αποκλειστικά στο loopback interface.
- Το Ollama θα προσπελαύνεται μέσω συγκεκριμένου, εγκεκριμένου τοπικού endpoint.
- Δεν επιτρέπεται αυθαίρετη διεύθυνση παρόχου από κείμενο χρήστη ή παραγόμενο περιεχόμενο.
- Δεν ενεργοποιείται δημόσιος server, Cloudflare Tunnel ή απομακρυσμένη πρόσβαση.
- Δεν επιτρέπεται αυτόματη μετάπτωση σε cloud μοντέλο όταν το τοπικό μοντέλο αποτύχει.
- Η τοπική πρόσβαση δεν θεωρείται από μόνη της επαρκής μηχανισμός αυθεντικοποίησης.

Η χρήση του Ollama δεν αποδεικνύει από μόνη της ότι η εγκατάσταση είναι πλήρως offline. Η πραγματική δικτυακή συμπεριφορά πρέπει να ελεγχθεί.

## 4. SEC-02 — Προστασία προσωπικών δεδομένων

Τα προσωπικά κείμενα αντιμετωπίζονται ως ιδιωτικά δεδομένα του χρήστη.

### Υποχρεωτικές απαιτήσεις

- Τα κείμενα επεξεργάζονται τοπικά κατά την κανονική λειτουργία.
- Δεν αποστέλλονται αυτόματα σε cloud AI, analytics ή άλλες υπηρεσίες.
- Δεν αποθηκεύονται στο GitHub, ακόμη και αν το repository είναι private.
- Δεν εμφανίζονται σε logs, screenshots, δοκιμές, GitHub Issues ή Pull Requests.
- Η εφαρμογή διαβάζει μόνο περιεχόμενο που επιλέγει ρητά ο χρήστης.
- Ο χρήστης ελέγχει πότε και πού αποθηκεύονται ή εξάγονται τα αποτελέσματα.

Η τοπική αποθήκευση και τα backups πρέπει να προστατεύονται ανάλογα με την ευαισθησία τους.

Δεν θεωρούμε ότι η τοπική αποθήκευση παρέχει αυτόματα κρυπτογράφηση.

## 5. SEC-03 — Data Integrity

Η εφαρμογή πρέπει να προστατεύει την ακεραιότητα των αρχικών δεδομένων.

- Το πρωτότυπο κείμενο διατηρείται ανεξάρτητο από το παραγόμενο.
- Η δημιουργία μετάφρασης ή νέου κειμένου δεν αντικαθιστά αυτομάτως το αρχικό περιεχόμενο.
- Η αποθήκευση και εξαγωγή απαιτούν σαφή ενέργεια του χρήστη.
- Η αντικατάσταση υπάρχοντος αρχείου απαιτεί κατάλληλη προειδοποίηση και έγκριση.
- Η αποτυχία επεξεργασίας δεν πρέπει να καταστρέφει την προηγούμενη έγκυρη έκδοση.
- Αν υλοποιηθεί μόνιμο ιστορικό, πρέπει να καθοριστούν οι κανόνες πρόσβασης, διατήρησης, διαγραφής και ανάκτησής του.

Οι απαιτήσεις ποιότητας μετάφρασης και πιστότητας περιεχομένου θα εξειδικευθούν στο SAF-001.

## 6. SEC-04 — Ollama & Model Security

Η σύνδεση με τα μοντέλα θα πραγματοποιείται μέσω ανεξάρτητου, ελεγχόμενου adapter.

### Απαιτήσεις

1. Εγκεκριμένο τοπικό endpoint.
2. Αναγνώριση των πραγματικά εγκατεστημένων μοντέλων.
3. Έλεγχος αναγνωριστικών μοντέλων.
4. Διακριτή αναφορά σφαλμάτων σύνδεσης και εξαγωγής αποτελέσματος.
5. Αποκλεισμός ανεπιθύμητων εξωτερικών μοντέλων και cloud inference.
6. Περιορισμός όγκου εισόδου, εξόδου και ταυτόχρονων εργασιών, ανάλογα με τις δυνατότητες του υπολογιστή.
7. Καμία εκτέλεση εντολών συστήματος μέσω των απαντήσεων του μοντέλου.

Τα αποτελέσματα AI αντιμετωπίζονται ως μη έμπιστο περιεχόμενο και όχι ως εντολές προς το λειτουργικό σύστημα.

## 7. SEC-05 — Ασφαλής εισαγωγή αρχείων

Εφόσον η εφαρμογή υποστηρίξει εισαγωγή TXT, DOCX ή άλλων τύπων αρχείων:

- Θα επιτρέπονται μόνο εγκεκριμένοι τύποι.
- Θα υπάρχουν κατάλληλα όρια μεγέθους.
- Θα ελέγχεται η πραγματική μορφή και εγκυρότητα του αρχείου.
- Θα αποτρέπεται η πρόσβαση σε μη επιλεγμένα αρχεία και διαδρομές.
- Θα αντιμετωπίζονται κακόβουλες δομές ή υπερβολικά μεγάλα περιεχόμενα.
- Τα εισαγόμενα έγγραφα δεν θα μπορούν να ενεργοποιούν εντολές, scripts ή εργαλεία.

Η εισαγωγή αρχείου δεν παρέχει εξουσιοδότηση για πρόσβαση σε άλλους φακέλους.

## 8. SEC-06 — Prompt Injection & AI Security

Το κείμενο που εισάγει ο χρήστης για επεξεργασία θεωρείται δεδομένο και όχι πηγή εξουσιοδότησης για την εφαρμογή.

Αν ένα έγγραφο περιέχει οδηγίες όπως «αγνόησε τους κανόνες σου», αυτές αντιμετωπίζονται ως τμήμα του εγγράφου, όχι ως εντολές που επιτρέπεται να αλλάξουν τη συμπεριφορά της εφαρμογής.

### Κανόνες

- Διαχωρισμός system instructions και περιεχομένου χρήστη.
- Καμία πρόσβαση του μοντέλου σε shell commands.
- Κανένα αυτόνομο άνοιγμα ή τροποποίηση αρχείων.
- Καμία αυτόνομη δικτυακή ενέργεια.
- Καμία αλλαγή configuration μέσω παραγόμενου κειμένου.
- Καμία αυτόματη χρήση μη εγκεκριμένων εργαλείων.

Οποιαδήποτε μελλοντική δυνατότητα AI tools θα απαιτεί νέα αξιολόγηση κινδύνου και ξεχωριστή έγκριση.

## 9. SEC-07 — Windows Environment Security

Η εφαρμογή θα λειτουργεί με τα δικαιώματα του συνήθους λογαριασμού χρήστη.

Δεν απαιτούνται δικαιώματα Administrator κατά την καθημερινή χρήση.

Εγκατάσταση προγραμμάτων, αλλαγή υπηρεσιών, λήψη μοντέλων και τροποποίηση του συστήματος απαιτούν προηγούμενη επιβεβαίωση.

Προτεραιότητα δίνεται στην επαναχρησιμοποίηση ήδη εγκατεστημένων και συμβατών εργαλείων.

Δεν επιτρέπεται αυτόματη εγκατάσταση λογισμικού χωρίς σαφή, χωριστή έγκριση.

## 10. SEC-08 — Dependencies & Supply Chain

Οι βιβλιοθήκες, τα εργαλεία και τα μοντέλα αποτελούν εξαρτήσεις που πρέπει να ελέγχονται.

- Επιλογή αξιόπιστων πηγών.
- Καταγραφή εκδόσεων.
- Έλεγχος γνωστών ευπαθειών.
- Έλεγχος ακεραιότητας πακέτων όπου υποστηρίζεται.
- Αξιολόγηση αδειών χρήσης.
- Ελεγχόμενες ενημερώσεις.
- Αποφυγή μη αναγκαίων dependencies.

Δεν εγκαθιστούμε νέα βιβλιοθήκη όταν η απαιτούμενη λειτουργία καλύπτεται κατάλληλα από ήδη διαθέσιμη, συντηρούμενη υποδομή.

## 11. SEC-09 — GitHub Security

Το repository παραμένει private, εκτός αν εγκριθεί μελλοντικά διαφορετική απόφαση.

Ελάχιστοι έλεγχοι:

- Κατάλληλο `.gitignore`.
- Αποκλεισμός τοπικών βάσεων, ιστορικών, logs και προσωπικών εγγράφων.
- Απαγόρευση commits με credentials, secrets ή tokens.
- Secret scanning όπου διαθέσιμο.
- Dependency scanning κατάλληλο για την επιλεγμένη τεχνολογία.
- Έλεγχος τροποποιημένων αρχείων πριν από κάθε commit.
- Ελεγχόμενη πρόσβαση και δικαιώματα.
- Εφαρμογή των εγκεκριμένων Git και AI agent κανόνων του REP-001.

Το private repository μειώνει τη δημόσια έκθεση, αλλά δεν αποτελεί υποκατάστατο των ελέγχων ασφαλείας.

## 12. SEC-10 — Logging & Diagnostics

Η εφαρμογή πρέπει να παρέχει αρκετές διαγνωστικές πληροφορίες ώστε να εντοπίζονται τεχνικά προβλήματα.

Τα logs θα καταγράφουν κατάλληλες πληροφορίες όπως:

- Κατηγορία σφάλματος.
- Χρονική στιγμή.
- Σχετική λειτουργία.
- Τεχνική κατάσταση υπηρεσίας.
- Κωδικό ή αναφορά διαγνωστικού συμβάντος.

Δεν θα καταγράφουν από προεπιλογή ολόκληρα prompts, μεταφράσεις, προσωπικά κείμενα, διαδρομές ιδιωτικών αρχείων ή ευαίσθητα δεδομένα.

Θα καθοριστούν όρια μεγέθους, διατήρησης και ασφαλούς διαγραφής.

Το HLT-001 θα προσδιορίσει τα αναγκαία health indicators.

## 13. SEC-11 — Updates & Recovery

Η εφαρμογή δεν θα εγκαθιστά ενημερώσεις αυτόματα.

Κάθε αλλαγή που επηρεάζει το τοπικό περιβάλλον θα πρέπει να έχει γνωστή πηγή, σαφή σκοπό, επιβεβαιωμένο scope και κατάλληλη διαδικασία ελέγχου.

Αναβαθμίσεις δεν πρέπει να διαγράφουν ή να αντικαθιστούν προσωπικά δεδομένα χωρίς ρητή έγκριση.

Η διαδικασία ανάκτησης θα λαμβάνει υπόψη:

- Αποτυχία εκκίνησης.
- Ασυμβατότητα μοντέλου.
- Αποτυχία εγκατάστασης ή ενημέρωσης.
- Απώλεια ή αλλοίωση τοπικών δεδομένων.
- Επαναφορά στην προηγούμενη επιβεβαιωμένη έκδοση.

Οι αναλυτικές απαιτήσεις αξιοπιστίας και ανάκαμψης ανήκουν στο HLT-001.

## 14. SEC-12 — Security Risk Assessment

Πριν από την αρχική υλοποίηση θα καταρτιστεί Project Threat Model.

### Αρχικοί κίνδυνοι προς αξιολόγηση

| Κίνδυνος | Βασική αντιμετώπιση |
|---|---|
| Μη εξουσιοδοτημένη δικτυακή πρόσβαση | Loopback binding και έλεγχος προέλευσης αιτημάτων |
| Διαρροή προσωπικών κειμένων | Τοπική επεξεργασία, data minimization |
| Prompt injection | Διαχωρισμός δεδομένων και εντολών |
| Κακόβουλο εισαγόμενο αρχείο | Validation και περιορισμένη πρόσβαση |
| Μη εγκεκριμένη χρήση cloud μοντέλου | Explicit local-model allowlisting |
| Ακούσια αντικατάσταση αρχείου | Έγκριση και έλεγχος ακεραιότητας |
| Ευπαθής εξάρτηση | Dependency review και ενημερώσεις |
| Κακόβουλη ή ακούσια αλλαγή κώδικα | Git controls, tests και ανθρώπινη έγκριση |

Η πιθανότητα και η σοβαρότητα κάθε κινδύνου θα αξιολογηθούν μετά την επιβεβαίωση της πραγματικής αρχιτεκτονικής.

Ο πίνακας δεν αποτελεί ολοκληρωμένη ή επαληθευμένη αξιολόγηση κινδύνου.

## 15. Security Verification & Acceptance

Το SEC-001 θα χρησιμοποιεί το Security Gate του DNA.

Πριν θεωρηθεί η πρώτη έκδοση ασφαλής για την εγκεκριμένη προσωπική χρήση, πρέπει να επιβεβαιωθούν τουλάχιστον:

| Κριτήριο | Προβλεπόμενη επαλήθευση |
|---|---|
| Τοπικό Ollama endpoint | Έλεγχος πραγματικής σύνδεσης |
| Μη έκθεση υπηρεσίας σε δημόσιο δίκτυο | Έλεγχος binding και πρόσβασης |
| Αποκλεισμός cloud fallback | Αυτοματοποιημένο test |
| Ασφαλής χειρισμός εισόδων | Validation και αρνητικά tests |
| Απουσία secrets και προσωπικών δεδομένων στο Git | Repository scan |
| Προστασία πρωτοτύπων | Functional και regression tests |
| Ελεγχόμενες ενημερώσεις | Έλεγχος διαδικασίας και συμπεριφοράς |
| Προστασία από prompt-based actions | Security regression tests |
| Εφαρμογή επιλεγμένων Shield controls | Security Plan και evidence |

Οι καταστάσεις ελέγχου θα διακρίνονται σαφώς σε PASS, FAIL, BLOCKED, NOT TESTED ή TECHNICALLY UNAVAILABLE, όπου εφαρμόζονται.

Δεν θα δηλώνεται επαλήθευση χωρίς πραγματικά στοιχεία.

## 16. Σχέση με Strong Room

Το Strong Room v1 είναι πρότυπο του Shield για ιδιωτικές HTTP εφαρμογές με συγκεκριμένες απαιτήσεις δικτυακής υποδομής.

Δεν επιλέγεται ως αρχιτεκτονική της αρχικής, προσωπικής, local-only εφαρμογής.

Αν μελλοντικά αποφασιστεί απομακρυσμένη πρόσβαση ή φιλοξενία, θα επανεξεταστούν το threat model και η καταλληλότητα του Strong Room ή άλλων απαιτούμενων ελέγχων.

## 18. Όριο ευθύνης

Το SEC-001 προστατεύει την εφαρμογή, το περιβάλλον και τα δεδομένα από κινδύνους κυβερνοασφάλειας.

Το HLT-001 εξειδικεύει την τεχνική υγεία, τη διαθεσιμότητα, την απόδοση και την ανάκαμψη.

Το SAF-001 εξειδικεύει την ασφαλή συμπεριφορά της AI, την ανθρώπινη έγκριση και την ποιότητα του παραγόμενου περιεχομένου.

Κανένα από αυτά τα πρότυπα δεν αντικαθιστά τα υπόλοιπα.
